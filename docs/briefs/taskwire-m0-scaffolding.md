# M0 - repository scaffolding

## 1. Goal

At the end of this milestone the repository `taskwire` exists and is buildable,
lintable and testable on both sides: a Python package `taskwire` (PyPI:
`taskwire`) with **zero required runtime dependencies**, and an npm package
`taskwire` with four subpath entry points. No library behaviour is implemented -
only the skeleton, the toolchain, the version-sync test and the dependency-isolation test. The
property this milestone exists to establish, and which every later milestone depends on, is that
**core installs, imports and passes its whole test suite with none of `redis`, `celery`, `fastapi`,
`muxws`, `vue` or `vuetify` present.**

## 2. Prerequisites

None. This is the first milestone. Do not `git clone` the sibling repo - reproduce the files below.

## 4. Normative rules in force

- **TW-CORE-006** Python core MUST NOT import FastAPI, Celery, Redis, or fastapi-viewsets. Framework
  imports are confined to `taskwire.contrib.*`. The npm core MUST NOT import Vue, Vuetify or the
  modal kit outside a subpath export.
- **TW-TS-010** `taskwire` MUST NOT declare Vue, Vuetify or
  `@dynamicforms/vuetify-modal-form-kit` as dependencies. The dialog adapter and `TaskwireFooter`
  ship in the `/vuetify` subpath only.
- **TW-PKG-001** The repository MUST ship one Python package and one npm package on a single version
  stream (`pyproject.toml` and `package.json` carrying identical `X.Y.Z`).
- **TW-PKG-002** `conformance/` MUST hold language-neutral JSON fixtures read **in place** by both
  `pytest` and `vitest`. There MUST be no copy step.
- **TW-CORE-011** `Envelope.v` MUST be the integer `1`. It is bumped only on a breaking wire change,
  never on an implementation change; package semver tracks the implementation and says nothing about
  the wire.
- **TW-REST-001** The REST path MUST work with zero optional dependencies installed. Handlers MUST be
  plain async functions of `(client, token, body) -> (status, payload)` with no framework types.
  Adapters `taskwire.contrib.fastapi.router()` and `taskwire.contrib.asgi.app()` MUST be the
  only places a web framework is imported.
- Packaging (spec §1): Python package root `taskwire`, extras `[redis]`, `[muxws]`, `[fastapi]`,
  `[celery]`; npm package `taskwire` with subpath exports `/vue`, `/muxws`,
  `/vuetify`.

## 5. Implementation notes

- **Zero runtime dependencies is a hard constraint, not an aspiration.** Do not add
  `typing_extensions`, `pydantic` or `attrs`. Models in later milestones are plain dataclasses. For
  3.10 compatibility of `X | Y` inside annotations, put `from __future__ import annotations` at the
  top of every core module.
- **The one deliberate divergence from the sibling repo's vite config:** it uses
  `formats: ['umd', 'es']`, which requires a single entry point. This package has four, and UMD
  cannot express four, so it builds `['es', 'cjs']` and the `exports` map's `require` entries point
  at the `.cjs` files. Everything else in the vite config is reproduced unchanged.
- `taskwire/conformance.py` is a shipped module that contains `assert` statements (it is the
  exported store conformance suite, TW-STORE-012). Ruff's `S101` bans `assert` outside `*_test.py`,
  so the per-file-ignore above is required - do **not** solve it by renaming the module or by
  replacing the asserts with `if ...: raise`.
- Ruff lint rules that will bite even in this milestone: `Q` (double quotes in Python), `I` with
  `lines-between-types = 1` (a blank line between the `import x` block and the `from x import y`
  block), `UP` (`str | None`, never `Optional[str]`), `N` (module names snake_case).
- Prettier/eslint rules that will bite on the TS side, and are the opposite of the Python ones:
  **`singleQuote: true`**, `printWidth: 120`, `trailingComma: 'all'`, `arrowParens: 'always'`.
  **`unicorn/filename-case: kebabCase`** - every `.ts` file is `stream-state.ts`, never
  `streamState.ts`. `import/order` requires `newlines-between: 'always'` and case-insensitive
  ascending alphabetisation. **`no-restricted-syntax` forbids `for...in`** - use
  `Object.keys/values/entries`.
- TS tests are `*.spec.ts` colocated beside the source; Python tests are `<module>_test.py` colocated
  beside the source. There is no `tests/` directory on either side.
- The two `.gitkeep` files under `conformance/` exist so the directory survives a clone; M1 replaces
  them with real fixtures.

## 6. Tests to write

1. `taskwire/packaging_test.py::test_python_and_npm_versions_match` - reads
   `taskwire.__version__` and the `version` field of the repository's `package.json` (locate it
   relative to `__file__`, not to the cwd) and asserts they are the identical string. Acceptance
   criterion for TW-PKG-001.
2. `taskwire/packaging_test.py::test_core_imports_no_optional_dependency` - `import taskwire`,
   then assert that none of `fastapi`, `celery`, `redis`, `muxws`, `django` appears in `sys.modules`.
   Run it as the first import in a fresh interpreter (`subprocess` with `sys.executable -c`) so an
   earlier test's import cannot mask a violation. This is the acceptance criterion for TW-CORE-006
   and it must keep passing in every later milestone.
3. `taskwire/packaging_test.py::test_py_typed_is_packaged` - asserts
   `importlib.resources.files("taskwire").joinpath("py.typed").is_file()`.
4. `taskwire/packaging_test.py::test_conformance_directory_is_readable` - resolves
   `conformance/wire` relative to the package and asserts the directory exists. Pins TW-PKG-002's
   "read in place" from the Python side.
5. `ts/packaging.spec.ts::version matches pyproject` - reads `taskwire/__init__.py` as text,
   extracts `__version__`, asserts it equals the version in `package.json`. The mirror of test 1.
6. `ts/packaging.spec.ts::conformance fixtures are reachable from vitest` - resolves
   `../conformance/wire` and asserts the directory exists.

## 7. Done when

Every command below runs from a clean checkout and passes.

- [ ] `python -m venv .venv && .venv/bin/pip install -e .` succeeds **and installs nothing but
      `taskwire`** (no fastapi, no redis, no celery in `pip list`).
- [ ] `.venv/bin/python -c "import taskwire; print(taskwire.__version__)"` prints `0.1.0`.
- [ ] `.venv/bin/pip install -e ".[dev]" && .venv/bin/pytest` passes with **no optional extra
      installed** - this is the property the whole design rests on, and it is a done-when check
      rather than a note.
- [ ] `ruff check . && ruff format --check .` is clean.
- [ ] `npm install && npm run lint && npm run build && npm run test` all pass.
- [ ] `dist/` contains `index.js`, `index.cjs`, `vue.js`, `muxws.js`, `vuetify.js` and one rolled-up
      `index.d.ts`.
- [ ] `npm run docs:build` produces a VitePress site with a Guide and an API Reference entry in the
      sidebar.
- [ ] `pip install ".[redis]"`, `".[celery]"`, `".[fastapi]"`, `".[muxws]"` each resolve.

## 8. Out of scope

Everything the library does. No models, no store, no reporter, no REST handlers, no client - M1 and
later own all of it. `ts/vue.ts` (M1c), `ts/muxws.ts` (M5) and `ts/vuetify.ts` (M7b) are empty
modules with an `export {}` in this milestone; they exist now only so the `exports` map and the build are correct
before anything needs them. Do not add CI configuration, a changelog, or publishing workflows.
